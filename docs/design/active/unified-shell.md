## What the owner asked

"I want the top bar from the Friday desktop's start screen visible on every workspace when
open in a new tab. I want the model selector visible, I want the chat popout visible, and I
want to align the workspace to fullscreen WITH the chat tray if the user so chooses... Also,
why does it say 'Friday by FutureSpeak.AI' instead of 'Agent Friday by FutureSpeak.AI'?
Where'd my Agent go? That's a TM, by the way. Let's TM it in the app and whenever Agent
Friday says the words 'Agent Friday'."

**Why the Agent went missing.** The wordmark is not the product name. The desktop's top
bar and the tab header print `settings.agent_name`, the name the user gave her at birth
("Friday" for the owner), followed by "by FutureSpeak.AI". Brand surfaces and her own name
were never told apart.

**The guard.** `tests/unit/test_product_name.py` fails when a UI string (the page sources,
the static scripts and pages, and the Python surfaces above) names the product "Friday by
FutureSpeak" or writes "Agent Friday" without ™. Comments, docstrings and text a model or a
voice reads are not UI strings; a model-facing string in a scanned file says so with a
`brand: plain` marker on its line.

## 2. ™ in what she says: display only

One filter, `brand.tm(text)` in Python and `fridayTM(text)` on the page, turns "Agent
Friday" into "Agent Friday™" in rendered text:

- idempotent: never `™™`, and it leaves "Agent Friday®" and "Agent Friday (TM)" alone;
- skips fenced code blocks and inline code;
- matches the words, not substrings: `agent_friday`, `agent-friday` and URLs are untouched.

It runs where text is shown: her chat replies and voice transcript lines, toasts, the
notification list and OS notifications, and exports. It never runs on what is stored, what
a model reads, or what is spoken. Audio gets plain "Agent Friday": `brand.spoken(text)`
strips the mark at every synthesis entry (cloud and local TTS, the local voice session,
podcasts, the ElevenLabs tool), so she never says "T M". The mark is not added to any
prompt.

## 3. The product and her name

The product is always Agent Friday™. Her own name is what the user chose at birth
(`settings.agent_name`; "Friday" for the owner). Brand surfaces (the wordmark, titles, the
tray, published pages, exports, the About card) use the product name. Conversation (her
replies, greetings, cards that speak for her) uses her name. BRAND.md records the rule.

## 4. One top bar everywhere

The start screen's top bar becomes one definition in `App`, rendered on the desktop and in
every workspace tab (a tab is rendered by `App`, so the bar and the chat tray use the same
state in both). The tab's separate header goes.

Left to right: the lockup; the context slot; the model selector (`QuickSwitch`); then the
notifications bell, Quick Draft, the chat button, fullscreen with chat (§5), settings, the
resource strip and the connection light.

| Control | Desktop | Tab |
|---|---|---|
| Lockup | opens System (as now) | back to the desktop, this workspace open |
| Context slot | holographic scene menu and orbs | the workspace's icon and name |
| Model selector | as now | the same menu, same effect |
| Chat | opens the docked chat tray | opens the same tray docked in this tab; the tray's own pop-out still makes a chat tab |
| Settings | opens Settings | opens the same Settings panel in the tab |
| Camera | as now | not shown: it drives the scene, which a tab does not render |

The scene and the hologram are untouched (their code belongs to the avatar session). A tab
renders no scene, so the bar cannot cover the hologram there; on the desktop the bar is the
one that is already there.

## 5. Fullscreen with the chat tray

A per-workspace choice: the workspace fills the screen and the chat tray docks beside it,
side by side, never over it.

- **Desktop:** the workspace window takes the maximized state, its right edge stops at the
  tray's left edge, and the dock hides (a hover at the bottom edge brings it back).
  **Tab:** the workspace fills the tab and the tray docks on the right.
- **Remembered per workspace**, on the server (`settings.workspace_layouts`, workspace id
  to `"fullscreen_chat"`), so the desktop and its tabs agree even on different addresses.
  Opening a workspace that remembers it opens it that way.
- **One keystroke:** Ctrl+Shift+F (Cmd+Shift+F) toggles it for the focused workspace. It is
  in the command palette too, and in the bar.
- **By voice and chat:** `set_workspace_layout(workspace?, fullscreen_chat)`, per the voice
  tool contract: declared in `_VOICE_LIVE_TOOLS` and the chat registry, routed through
  `_governed`, internal (the owner's own screen, ring 1). No workspace named means the
  focused one. It saves the choice and sends a `layout` action to the page the user is
  looking at (the bus ranks the focused page first for this), and says LAYOUT_OK only when
  the page reports that it applied it.

"Fullscreen" means filling Friday's screen, not the browser's F11 mode: a spoken command is
not a user gesture, so a page may not enter browser fullscreen on its behalf. F11 composes
with it.

## 6. The normalization audit (start of P-BRAND-FIDELITY)

Every registry workspace is captured at one viewport (1600 by 1000) in both contexts, a
desktop window and its own tab, plus the start screen, one browser at a time, and every
frame is looked at. Captures stay on this machine; they hold the owner's data.

The inventory covers: headers, titles, favicons (the rocket), type and colour tokens,
buttons, empty, loading and error states, approval cards, toasts, the settings entry,
shortcuts and the command palette, and where the voice button sits. Each finding is listed
in `docs/brand/fidelity-audit.md` with the fix made in this pass, or the reason it is left
(for example, the avatar session's own controls). Bars: Linear and Superhuman for
consistency, and the brand check in BRAND.md.

Decisions taken here, for the owner's veto:

- **Favicon:** the rocket on every Friday page; tabs are told apart by their titles, which
  start with the workspace or the item. (Tabs showed the workspace icon until now.)
- **Tab lockup click:** goes to the desktop; on the desktop it still opens System.
- **Camera and the scene menu** stay desktop-only.
